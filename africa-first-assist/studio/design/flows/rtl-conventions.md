# RTL and FR/AR conventions (provisional defaults)

Date: 2026-11-18
Status: **DRAFT. Provisional defaults for the pitch mock-ups, to test with users.** Any AR screen in the deck uses these, so the deck does not decide them by accident (critic finding 14). Each default lists why and how to test it.
Applies to: all flows 00–09. Features X9 (FR/AR + RTL), X10 (accessibility).

## Defaults
| # | Topic | Default | Why | Test / confirm |
|---|---|---|---|---|
| R1 | Digits | **Western digits 0–9 in both FR and AR UI.** No Eastern Arabic digits (٠١٢٣) | Common in Moroccan Arabic print and signage (A). Same digits as on plates, ID cards, passports (MRZ), bank cards and phone keypads. A user reading a number to an agent sees the same digits as the agent. One digit set lowers entry errors in OTP, policy and phone fields | Preference test in AR with S1–S3 users; check AFA's existing AR documents |
| R2 | Number direction | Every number run (phone, policy, case reference, amount, IBAN/RIB, guest code) is an isolated LTR run inside RTL text (`<bdi>` / FSI–PDI) | Stops bidi reordering of mixed strings such as "+212 6 12 34 56 78" | Automated bidi check on all AR strings |
| R3 | Phone numbers | `+212 6 12 34 56 78`, groups of two. Tap-to-call shows the full number as text | Matches Moroccan writing (A); readable digit by digit by screen readers | Screen-reader test FR and AR |
| R4 | Vehicle plates | **Shown as on the physical Moroccan plate**: serial number, Arabic letter, region code, in plate order, as one LTR-isolated block, e.g. `12345 \| ب \| 6`. The Arabic letter stays Arabic in FR UI too. Input: three fields (number, letter picker, region code), with Latin aliases accepted in the picker (e.g. "B" finds ب). Foreign and temporary plates: free text | The plate is what the driver and the tow provider see on the car. Three fields avoid bidi typing errors. Same display in FR and AR | Check plate format and letter list with AFA roadside team; usability test of the letter picker |
| R5 | Dates | **Gregorian calendar, day-month-year, in both languages.** Long form with month names where space allows: FR "18 novembre 2026", AR with Moroccan month names (e.g. "18 نونبر 2026", A). Short form `18/11/2026`. ISO 8601 in data. No Hijri dates by default | Contracts, visas, flights and certificates are Gregorian. Spelled-out months avoid DD/MM vs MM/DD confusion for MRE and foreign users | Confirm AR month names with an AR copywriter; ask in tests if Hijri is wanted anywhere (e.g. as an optional extra line) |
| R6 | Time and money | 24-hour time (`14:30`). Amounts `1 234,00 MAD`: space for thousands, comma for decimals, ISO code MAD in both languages, isolated LTR in AR | Matches French and Moroccan formats (A). One code avoids mixed currency labels [DR O-U5] | Test "MAD" vs "درهم" in AR |
| R7 | **SOS position** | **Not mirrored, because it does not need to be.** SOS is a fixed full-width bar docked directly above the bottom tab bar (at the bottom of screens with no tabs: welcome, login, OTP, app lock screen, forms). Inside the bar, icon and label order follow the language (icon first in reading direction). When the on-screen keyboard is open, the bar collapses to a fixed SOS button in the top app bar, still one tap | Same place in FR and AR, so bilingual households and users who switch language keep the same muscle memory. Bottom of screen is within thumb reach. Reserved layout space: never covers content or focus (2.4.11), reflows at 320 px (1.4.10), no overlap at 200% text (1.4.4). At least 8 px gap from the tab bar to limit mis-taps (2.5.8). Accidental taps are caught by the single confirm (flow 02) | First-click test under time pressure, FR and AR; accidental SOS rate in pilot; 200% text check on smallest supported phone |
| R8 | Mirroring | Mirror layout, navigation, back arrows, progress steps, timelines, sliders. Do **not** mirror: maps, phone and clock icons, media controls, logos, plates, numbers, QR codes, MRZ | Platform RTL guidelines (Apple HIG, Material) | Visual QA in AR |
| R9 | Mixed scripts | Latin names from passports stay Latin in AR UI. FR product names inside AR text are isolated. Text fields set direction from the first strong character. The assistant accepts Darija in Latin or Arabic script (best effort, flow 07) | Data must match documents exactly; mixed input is normal in Morocco (A) | Bidi QA; AR content review |
| R10 | Type | Arabic font with a larger base size than Latin where needed for legibility (A: +1 to +2 pt), same line-height rules; no all-caps for emphasis | Arabic glyphs read smaller at the same point size | Legibility test at default and 200% text |
| R11 | SMS | Arabic SMS uses Unicode (70 characters per part). Critical SMS are written to fit, with the case reference and 24/7 number first | Cost and truncation | Send tests on Moroccan networks |
